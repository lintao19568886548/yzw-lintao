# 云园慧控待租厂房功能说明

**作者**：周茂森

**文档定位**：`docs/` 系统设计文档系列第八篇。本篇讲租赁分组下的「待租厂房」——它不录入任何数据，却是系统里唯一**面向招商**的页面。第一章解释它为什么存在（与园区管理有何不同），第二至四章讲怎么用与数据怎么来，第五章起是权限与边界。全部结论出自仓库当前代码。台账侧见 [园区管理.md](园区管理.md)。

---

## 第一章　它是什么、为什么存在

### 1.1 一句话

把当前权限范围内**所有还有空置面积的厂房**汇总成一份清单，按空置规模自动排出招商优先级——**空置面积就是还没赚到的钱，这一页把它变成一份可以直接拿去谈的名单。**

页面副标题原文：

> 聚合当前权限范围内仍有可租面积的厂房，按招商优先级与空置面积实时排序。

### 1.2 园区管理里已经有「可招商面积」了，为什么还要单独一页

这是本篇要回答的核心问题。两个页面读的是**同一批数据**，但回答的是**两个不同的问题**：

| | 园区管理 | 待租厂房 |
| --- | --- | --- |
| 聚合单位 | 按**园区** | 按**厂房** |
| 回答的问题 | 我这个园区**经营得怎么样**（出租率多少） | 我现在**有什么能卖**（哪几栋、多大、什么价） |
| 时间指向 | 回顾已经发生的 | 面向还没发生的 |
| 使用者 | 园区经理、老板 | 招商人员 |
| 能否修改 | 能（录入、编辑、归档） | **只读** |

园区管理页呈现的是「该园区可招商 3000 ㎡」——此为一项**统计数字**。待租厂房页则将这 3000 ㎡ 予以拆分：「3 号厂房 2 楼 1200 ㎡，挂牌 ¥25/㎡；5 号厂房整栋 1800 ㎡，挂牌 ¥22/㎡」——此为一份**可执行的清单**。前者用于汇报，后者用于执行招商工作。

### 1.3 它是系统里唯一朝外看的页面

清点一下系统的其余部分：合同管理记的是已签的约、账单记的是已发生的费用、巡检记的是已做过的检查、考勤记的是已上过的班——**全都在管理已经发生的事实**。

只有待租厂房这一页在管**还没发生的生意**。它盯着的是园区收入的缺口：每一平方米空置，都是每月固定在流失的租金。所以这一页的设计目标不是「记录准确」，而是**「让最该被处理的空置最先被看见」**。

### 1.4 自动优先级：把注意力引到该去的地方

清单不是按录入顺序排的，而是按可租面积自动分三档：

| 档位 | 阈值 | 含义 |
| --- | --- | --- |
| **优先招商** | 可租 ≥ 5000 ㎡ | 空得最多、损失最大，排最前 |
| **重点关注** | 可租 ≥ 1000 ㎡ | 值得主动跟进 |
| **常规待租** | 其余 | 有空置，但不急 |

**此三档由系统计算得出，非人工标注**——无须任何人维护「该厂房是否为重点」这一字段，因而不会出现「已标注为重点但实际早已出租」一类过期标记。排序规则同理：优先级高者在前，同档内面积大者在前。

### 1.5 只读是有意的，不是没做完

这一页**没有任何新增、编辑、删除按钮**（代码里连 reducer 调用层都没有引入）。原因是它的数据没有一项是「属于自己的」：

```text
可租面积 = 楼层总面积（园区管理录入） − 合同占用面积（合同签约产生）
```

两个来源都在别处维护，这一页只做减法。**因此它不需要、也不应该有任何可编辑字段**——一旦允许在这里改点什么，就等于凭空多出一份需要跟另外两处对账的数据，而对账迟早会漂。

模块注释里对这个原则有过一次直接表述（当时说的是园区列表页，逻辑相同）：

> 园区的浏览入口只有园区管理一处，这里不再有单独的园区列表页——两者展示的是同一批园区，只是维度不同，重复维护会漂移。

### 1.6 签约即下架，不需要人工维护

因为可租面积是实时算出来的，所以：**合同一签，占用的楼层面积立刻从可租里扣掉；扣到零，这栋厂房自动从待租清单消失**。反过来，合同注销后它自动回到清单里。

没有任何人需要去「下架」或「重新上架」一栋厂房。副标题里那个「实时排序」指的就是这条链路——它靠的是 SpacetimeDB 的实时订阅：合同关联表一变，页面立即重算。

## 第二章　列表页怎么用

### 2.1 四张统计卡

| 卡 | 含义 |
| --- | --- |
| **待租厂房** | 有可租面积的厂房数 |
| **覆盖园区** | 这些厂房分布在几个园区 |
| **优先招商** | 可租 5000 ㎡ 以上的有几处 |
| **可租总面积** | 全部待租厂房合计 |

> 四张统计卡呈现的是**全量数据**，不随下方筛选条件变化——它们回答的是「当前共有多少可租资源」，筛选仅用于在清单中定位具体条目。

### 2.2 筛选

三个条件：**关键词**（匹配厂房名、园区名、园区地址）、**所属园区**下拉、**招商优先级**下拉，外加一个「重置筛选」。任一条件变化都会回到第 1 页；筛选把结果变少导致当前页超出范围时，会自动回落到最后一页而不是显示空白。

**没有面积区间筛选**——面积维度已经由招商优先级表达了。

### 2.3 每张厂房卡片

- **首图**：取该厂房任一楼层的第一张照片，没有则显示「暂无图片」；
- **优先级徽章 + 园区名**；
- **厂房名 + 园区地址**；
- **可租面积**（单独放大突出——这是这一页的主信息）；
- 三项事实：总面积、楼层数、**最低挂牌租金**；
- 厂房说明（两行截断）；
- 「查看厂房详情」按钮。

**最低挂牌租金**的口径值得说明：只在**还有剩余面积**的楼层里取最低价——已经租满的楼层报价再低也没意义。全部楼层都没填价时显示「面议」。

> **挂牌租金 ≠ 成交价**。挂牌是对外报价，实际成交价谈在合同里，可能打折。这两个数字在系统里是分开的字段，不要混用。

### 2.4 厂房地址来自园区

厂房本身没有地址字段。同一园区的厂房共用园区地址，具体是哪一栋由厂房名称区分——这是一次刻意的简化，避免同园区几十栋厂房各自维护一遍相同的地址。

### 2.5 三种空状态，说的是三件不同的事

| 情况 | 提示 |
| --- | --- |
| 数据还在同步 | 「正在同步厂房与楼层数据，可租面积将在租赁资产订阅完成后自动计算。」 |
| 确实没有待租厂房 | 「当前没有待租厂房。厂房楼层的总面积已经全部出租，或尚未维护楼层面积。」 |
| 筛选后无结果 | 「没有符合条件的厂房。请调整厂房名称、园区或招商优先级后再试。」 |

第二条特意点出了「或尚未维护楼层面积」——**楼层面积没录的厂房不会出现在这份清单里**（见 §7.1），提示语提前说明了这件事，免得用户以为厂房丢了。

## 第三章　厂房详情页

从列表页点「查看厂房详情」进入，顶部有「← 返回待租厂房」。

| 区块 | 内容 |
| --- | --- |
| 页头 | 厂房名、所属园区与地址、右侧「可租 N ㎡」徽章 |
| 四张统计卡 | 总面积、可租面积、**待租楼层（有空置的层数 / 总层数）**、最低挂牌租金 |
| 现场图片 | 全厂房楼层图片去重后最多 6 张缩略图 |
| 厂房资料 | 所属园区、建成日期、产权类型（自有厂房 / 入驻厂房）、园区地址、厂房说明 |
| **楼层台账** | 九列表格：楼层、状态、总面积、已使用、可租、挂牌租金、层高、承重、说明 |

楼层表格是这一页的核心——**招商谈的是具体楼层，不是整栋厂房**。每层带一个状态徽章：还有空置的是「待租」，占满的是「已满」。这里用表格而不是卡片，代码注释写明了原因：「楼层是逐层对比面积与租金的场景，表格比卡片更好扫」。

**这一页没有任何招商动作**——没有意向登记、没有联系人、没有预约看房，纯展示。客户跟进目前在系统外进行（另见 §7.4）。

## 第四章　可租面积是怎么算出来的

### 4.1 公式

```text
某层可租 = 该层总面积 − 该层已被合同占用的面积   （结果不为负）
厂房可租 = 各层可租之和
```

「总面积」来自园区管理录入的楼层台账；「占用面积」来自**合同与楼层的关联表**，不是人工填的字段。

### 4.2 为什么这件事重要

系统里原本有一个人工维护的「已用面积」字段，后来被删掉了。负责计算的函数注释解释了为什么：

> 这是原来那个人工填写的 `used_area_centi_square_metres` 的替代品：楼层总面积固定在楼层上，占用面积由合同关联算出，两者相减即为可租。

人工维护的「已用面积」有个必然结局：签了合同忘了改、退租了忘了改，久而久之它和合同对不上，而**没有任何机制会发现这种不一致**。改成算出来之后，这一整类错误消失了。

同一段注释还提到一条纪律：

> 只排除已注销的合同，判定口径与服务端超额校验保持一致——两边一旦不同，界面显示的可租面积会和服务端愿意放行的面积对不上。

即：页面显示「尚可出租 500 ㎡」时，服务端就必须确实允许签订这 500 ㎡ 的合同。两侧口径必须同源。

### 4.3 一层分租给多户是支持的

同一层楼被两份合同各租一部分时，占用面积会**累加**，剩下的才是可租。这在计算函数里有单元测试锁定。

### 4.4 每层单独算，不互相抵消

某层若因数据错误出现「占用超过总面积」，它的可租面积按 0 计，**不会去抵消其他楼层的空置**。否则一层的数据错误会让整栋厂房凭空少掉一块可租面积。

## 第五章　权限

### 5.1 设计意图：招商角色可以只看不改

待租厂房的访问权限与**园区管理权限完全解耦**：

- 看待租厂房：只需要对应菜单授权；
- 改厂房台账：需要园区管理权限（`can_manage_rental`，与服务端 `require_rental_manager` 同口径）。

这正是为招商人员或外部中介准备的：给他们看得到存货清单的权限，但拿不到修改台账的权限。**详情页不需要单独授权**，跟着列表页的菜单走。

### 5.2 两处判定认同一组菜单（曾经不一致，2026-08-05 已修）

侧边栏是否显示「待租厂房」入口，判的是 `/rental/list`——这是已删除的园区列表页遗留下来的菜单行。之所以不改判新路径，是因为库里现有角色带的就是这条菜单，改了会让他们直接掉权。

问题在于**路由守卫原先只认 `/rental/factory`**，与侧边栏不是同一条菜单，造成两个方向都不对：

- 只授了 `/rental/list` 的角色：侧边栏能看到入口，**点进去被拦下**；
- 只授了 `/rental/factory` 的角色：能进页面，**但侧边栏没有入口**。

现已在权限归一化表里给 `/rental/factory` 补上等价路径，让它与详情页一并接受 `/rental/list` 与 `/rental/factory` 两条菜单中的任意一条，与园区档案页的处理方式一致。测试 `待租厂房与侧边栏判定同一组菜单` 覆盖了正反两个方向，以及「两条菜单都没有则进不去」。

## 第六章　与其他模块的关系

| 模块 | 关系 |
| --- | --- |
| **园区管理** | 上游。厂房、楼层、面积、挂牌租金都在那里录入；本页只读 |
| **合同管理** | 上游。合同占用楼层面积，直接决定这里还剩多少可租；签约即下架 |
| **租赁总览** | 数据流向图里「厂房」与「楼层」两个节点都可以点进本页；楼层节点还标着「N 满租 / M 待招商」 |
| **数据地图** | 厂房与楼层节点同样链到本页 |
| **运营总览** | 首页「资产与团队快照」卡片有「进入资产台账」链接指向本页 |

## 第七章　已知边界与待办

1. **楼层面积未维护的厂房不出现在清单里**：可租面积算出来是 0，被过滤掉。这与租赁总览的口径**不完全一致**——总览把「面积未维护」计入「待招商」，而这里把它排除。同一个厂房在两个页面上的归类可能不同，看数时要留意；
2. **挂牌租金没有标注计价周期**：字段注释只写「每平方米租金」，页面显示 `¥N/㎡`，没有「/月」。实际业务口径是按月，但代码与界面都没有把它写死，建议统一补上；
3. **首页的「进入资产台账」链接没有做权限判定**：无权限的账号点进去会被路由守卫拦下，体验上不如直接隐藏；
4. **没有招商动作**：本页只到「看见有什么可租」为止。意向登记、客户跟进、带看记录都不在系统内——若将来要做招商 CRM，这一页是天然入口。
