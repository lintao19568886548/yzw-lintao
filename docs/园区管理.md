# 云园慧控园区管理功能说明

**作者**：周茂森

**文档定位**：`docs/` 系统设计文档系列第三篇。前两篇讲横切机制（权限模型、抽象泄露评估），从本篇起按业务模块讲功能，第一个模块是「园区管理」。本文回答三个问题：这个页面承担什么职责、管理哪些数据对象、提供哪些操作与规则。全部结论出自仓库当前代码，关键处注明源文件；业务背景（园区老板—园区经理—厂房—租客）见 [权限模型设计.md](权限模型设计.md) §1.1，涉及平台与工程机制时引用 [server/ARCHITECTURE.md](../server/ARCHITECTURE.md)。

## 第一章　定位：全系统的空间资产总台账

### 1.1 职责一句话

园区管理负责**录入并维护运营方的全部空间资产**——园区主档，及其名下的厂房、楼层、宿舍、水电表——并以楼层台账为口径，给出每个园区的面积与出租率。

「台账」在本文中指：以数据库行为单位、逐项登记、可增删改查的资产清单——区别于原系统里散落在合同文本和账单备注中的自由文字。

### 1.2 为什么它是地基

系统里几乎所有业务数据都直接携带 `park_id`：租赁合同、财务流水、租金账单、报销、消防/变压器/电梯/维修等运维记录、门禁车辆与访客……全部挂在园区之下。因此：

- **启用系统的第一步就是在此录入园区**——没有园区，其余模块无处挂靠；
- **权限的数据范围以园区为单位**——给园区经理授权（`RolePark` / `UserPark`，见 权限模型设计.md §3.3）的标的，正是这里录入的园区。

### 1.3 对象层级

```text
园区 Park（主档：名称、地址、负责人、状态、说明、图片）
 ├── 厂房 Factory ────── 楼层 FactoryFloor（面积、层高、承重、挂牌租金）
 ├── 宿舍 Dormitory ──── 宿舍楼层 DormitoryFloor（房间数 × 单间面积）
 ├── 水电表 UtilityMeter（表号、类型、安装位置、倍率、分时标志）
 └──（合同、财务、运维、门禁等业务数据挂靠于园区，但不在本模块录入）
```

### 1.4 边界：哪些不归它管

| 事项 | 归属 | 与本模块的衔接 |
| --- | --- | --- |
| 变压器、电梯、消防、维修工单 | 独立的「维护管理」分组（四个页面，`/maintenance/*`）。变压器、电梯、消防均为**资产与巡检分离**的台账（录设备 → 打印巡检码 → 扫码或后台登记巡检，见 docs/ 第四至六篇；电梯必挂厂房、消防设施必挂厂房或宿舍楼层，灭火器按有效期自动提醒）；报修工单保留流程流水模型 | 园区档案页以**只读概览**展示各厂房的设施数量与巡检状态，并提供跳转到维护管理的入口（§2.3.1）；删除园区时运维记录是阻挡项（§4.3）。注意：维护菜单默认没有角色授权，非 Super 角色须在权限管理页显式勾选后才能看到 |
| 智能水电表设备绑定 | 智能水电表管理页（见 [智能水电表管理.md](智能水电表管理.md)） | 水电表表单里设备号只读展示，未绑定时给出跳转链接——设备号在这里手敲会敲错且不会报错 |
| 合同录入、楼层出租 | 合同管理页 | 合同占用楼层的关联数据反过来决定本模块的「已用面积」（§3.6） |

## 第二章　入口与页面组成

### 2.1 三个页面

侧边栏「租赁」分组下，本模块由三个页面构成（路由见 `src/router.rs`）：

| 路径 | 页面 | 职责 |
| --- | --- | --- |
| `/rental/manage` | 园区管理（主页面） | 园区台账：统计、筛选、新增、删除，及进入档案页的入口 |
| `/rental/detail/:id` | 园区档案 | 单个园区的完整档案：编辑主档，录入厂房、楼层、宿舍、水电表 |
| `/rental/overview` | 租赁总览 | 数据流向图（只读），暴露资产链路与数据质量 |

原系统的菜单路径 `/system/park` 与 `/rental/manage` 在权限判定上等价（`src/permissions/routes.rs`），老菜单数据不必迁移。

### 2.2 主页面（`src/pages/rental_management/overview.rs`）

自上而下四个区块：

1. **统计卡**：左卡为整体出租率百分比 + 进度条 + 「N 个园区 · M 份有效合同」；右卡为总面积、已出租、可招商、有效合同四项数字。
2. **筛选区**：关键词（匹配园区名、地址、负责人、电话）；出租率区间下拉（低于 50% / 50%–90% / 90% 以上）。
3. **园区台账表格**，九列：园区（名称+地址）、状态（运营中/已停用）、出租率（进度条）、总面积、已出租、可招商、有效合同、负责人、操作。
4. **行操作**：「经营详情」弹窗（面积磁贴 + 当前入驻合同列表，`detail.rs`）；「园区档案」跳转档案页；「删除」（带阻挡检查，§4.3）。

「新增园区」按钮与删除操作仅对持有园区管理权限的账号显示（§5）。

### 2.3 园区档案页（`src/pages/rental_list/detail.rs`）

单个园区的全部家当集中在这一页：图片画廊；九项事实（厂房面积、宿舍面积、厂房已租、厂房可租、厂房个数、宿舍个数、创建/更新时间、地址）；园区描述；以及四个资产区块——厂房（含其楼层）、宿舍（含宿舍楼层）、水电表、设施概览三卡。**厂房、楼层、宿舍、图片的录入统一在此完成**，主页面只管园区主档本身。

### 2.3.1 厂房设施概览三卡的设计

每个厂房下面挂着三张卡：消防设施、变压器、电梯。这三类设备**不在本页录入**（录入在维护管理，见 §1.4），因此这三张卡的职责只有两条：**让人一眼看出这个厂房的设施状况**，以及**在需要处理时把人送到该去的地方**。

#### 问题：早期实现的两处缺陷

1. **展示不可扩展**：变压器卡与电梯卡展示的是「该厂房第一台设备」的完整字段（名称、位置、规格、容量、最近巡检）。一台设备时卡片就被撑得很高，若厂房有三五台，这个结构无法容纳——而且「第一台」本身是按 id 取的，对用户没有任何意义；
2. **空状态是死胡同**：没有设备时只显示「暂无电梯信息」。用户想录入，点卡片点不动，本页也没有任何录入口，于是卡在这里——**这不是用户不会用，是页面没有告诉他该去哪**。

#### 设计原则

这三张卡是**体检报告，不是设备清单**。判断标准：读者在这一页要回答的问题是「这个厂房的设施有没有问题」，而不是「第 2 台变压器的规格是什么」——后者属于维护管理页。据此定三条规则：

1. **卡片高度必须与设备数量无关**——内容有界，不随设备增加而膨胀；
2. **异常必须显眼**——巡检异常、灭火器过期这类要出问题的事，是这三张卡存在的主要理由；
3. **每张卡都有出口**——无论有没有设备，都给一个明确的下一步动作。

#### 卡片内容

**变压器 / 电梯**（少数大件，逐台点名有意义）：

```text
变压器                                    2 台
──────────────────────────────
1 号变压器          正常    08-04
2 号变压器          异常    08-01     ← 异常行红色
──────────────────────────────
[ 查看并登记巡检 → ]
```

- 最多列 **3 台**，超出显示「还有 N 台」；
- 排序：**异常项置于前列**，其次按最近巡检时间倒序——须使存在问题的对象优先被看到；
- 每行：设备名 + 状态徽章 + 最近巡检日期（从未巡检显示「未巡检」）。

**消防设施**（数量多、同类小件，逐个点名没有意义）：

```text
消防设施                                 22 个
──────────────────────────────
灭火器 12 · 消防栓 4 · 消防出口 6
巡检异常 1 个        已过期 2 个        ← 非零时红色
──────────────────────────────
[ 查看并登记巡检 → ]
```

- 按**设施类型分组计数**，而不是逐个列出；
- 单列「巡检异常」与「已过期」两个计数（后者是灭火器有效期，见第六篇），**为零时不显示**，避免一片零值淹没真正的告警。

**两类卡片形态不同是有意的**：变压器电梯是「少数大件」，用户关心的是具体哪一台；消防设施是「大量同类小件」，用户关心的是总量与异常数。用同一种形态硬套，必有一边不好用。

#### 空状态：把死胡同改成入口

没有设备时不再只说「暂无」，而是给出原因与动作：

```text
变压器
该厂房还没有登记变压器
[ 去维护管理登记 → ]
```

按钮对**没有维护管理菜单权限**的账号也显示，但点击后落到维护页时会被路由权限拦下并提示——这比隐藏按钮好，因为用户至少知道了「这件事该在哪做、该找谁开权限」。

#### 跳转要带上厂房上下文

点击按钮跳到对应的维护管理页面（`/maintenance/transformer` 等），并**把当前厂房作为筛选条件带过去**，落地即是这个厂房的设备列表，而不是全园区几十条里让用户自己找。实现上给维护页的搜索框支持一个 URL 查询参数，跳转时填入厂房名称。

#### 区块标题也要改

现有小标题写的是「设施信息 · 最近一次检查」，与新的内容（数量、异常、到期）不符，改为「**设施概览 · 数量与巡检状态**」。

### 2.4 租赁总览（`src/pages/rental_management/flow.rs`）

将本模块的数据关系绘制为两条独立链路，并一并呈现数据质量状况：

- **空间资产链**「园区 → 厂房 → 楼层」：全程数据库外键，一路可追溯。节点上标注「N 挂靠园区 · M 未挂靠」「N 挂靠有效厂房 · M 归属已删厂房」等质量计数。
- **合同与客户链**「园区 → 合同 → 在租客户」：合同直接挂园区（外键）；合同与客户档案之间靠**姓名+电话文本匹配**，数据库里没有这条外键——箭头以推断样式绘制，并标注未归档份数。

两条链刻意分开画，因为合同表只有 `park_id`，没有指向厂房或楼层的字段（见 §3.6 与 §6）。

## 第三章　数据对象与录入字段

### 3.1 园区主档

表单（`src/pages/rental_management/form.rs`，新增与编辑共用一个弹窗）：

| 字段 | 约束 |
| --- | --- |
| 园区名称 | 必填，≤100 字 |
| 园区状态 | 启用 / 停用 |
| 详细地址 | 必填，≤200 字 |
| 负责人 | 必填，≤50 字 |
| 联系方式 | 必填，≤50 字 |
| 园区说明 | ≤300 字 |
| 园区图片 | 最多 8 张 |

两个设计决策值得单独说明：

- **园区表没有面积字段**（`tables/rental/park.rs` 注释）：原有的面积列已删除，园区面积一律由楼层台账实时算出——从结构上排除「录入面积与楼层加总不符」这类矛盾。
- **图片与主档同事务提交**：前端先把图片传至对象存储，再调用 `create_park_with_images` / `update_park_with_images` 一次写入，避免出现有档无图或有图无档的中间状态。

### 3.2 厂房

字段：厂房名称（必填）、建造时间（`YYYY-MM-DD`）、产权归属（自有/租入）、描述。`park_id` 由档案页上下文注入，不需要用户选择；`0` 是「尚未挂靠园区」的哨兵值（哨兵设计的完整评估见 [抽象泄露评估.md](抽象泄露评估.md)）。新增走 `create_factory_with_floors`，可以在建厂房的同一事务里带上整批楼层（单次至多 100 层）。

### 3.3 楼层

字段：楼层名称（必填）、层高（米）、承重（吨/㎡）、挂牌租金（元/㎡/月）、总面积（㎡）、描述、楼层图片。

- **定点数口径**：所有面积、长度、租金一律以**乘 100 的整数**存储（`centi_*` 列），输入端最多两位小数、拒绝负数——金额与面积不走浮点。
- **没有「已用面积」字段**：某层被租掉多少，由「合同—楼层」关联数据算出（§3.6），不允许手工录入一个可能与合同矛盾的数字。

### 3.4 宿舍

宿舍楼（名称、备注）+ 宿舍楼层（层号、房间数、单间面积、层高、挂牌租金——挂牌是对外报价，不是成交价）。宿舍面积 = 房间数 × 单间面积，逐层计算。

### 3.5 水电表

字段：表号（必填，**园区内唯一**）、类型（电表/水表）、安装位置（园区公共区域 / 某厂房楼层 / 某宿舍楼层，三选一）、倍率（必须大于 0）、分时计量标志（仅电表可用）、备注。智能水电表设备号只读展示，绑定操作在智能水电表管理页完成（[智能水电表管理.md](智能水电表管理.md) §3）。

这张台账的建表动因记录在 `tables/rental/assets/meter.rs` 的模块注释里：原系统 1200 多条账单明细中，262 条表计名为空、91 条把「尖峰平谷」填进了表计名——水电表因此从账单里的自由文本升格为独立台账。

### 3.6 面积与出租率的统计口径

主页面副标题写明「以厂房楼层为统计口径」，具体规则（`model.rs`，各规则均有中文命名测试）：

- **园区厂房面积** = 各厂房楼层 `total_area` **逐层求和**——不是「首层面积 × 层数」（测试：`厂房面积逐层求和而不是首层乘层数`）；
- **已出租面积** = 有效合同经「合同—楼层」关联表占用的楼层面积之和；有效合同排除已删除、非交易类型及已过期/已退租状态（`is_active_income_contract`）；
- **出租率** = 已出租 / 厂房楼层总面积；宿舍面积单独统计，不计入出租率；
- **可招商面积** = 总面积 − 已出租。

## 第四章　操作与校验规则

### 4.1 录入分工

园区主档在主页面新增；厂房、楼层、宿舍、水电表在园区档案页录入。每类资产都是「新增 / 编辑 / 删除」一套操作，前端服务层一一对应服务端 Reducer（`src/services/rental_management/`）。

### 4.2 服务端校验规则

写入侧的校验集中在 `server/spacetimedb/src/reducers/rental/` 下，其中 `check_*` 均为 `#[pure_function::pure]` 标注的纯函数（宏机制见 ARCHITECTURE.md §3.8）：

| 对象 | 规则 |
| --- | --- |
| 园区 | 名称、地址等必填与长度校验（`validated_park`）；图片至多 8 张 |
| 厂房 | 名称必填；`park_id` 非 0 时必须落在调用者数据范围内 |
| 楼层 | 名称必填；租金、面积、层高、承重不得为负 |
| 合同占用楼层 | 楼层与合同必须同园区（`check_same_park`）；占用面积非负且不得超过该层总面积（`check_floor_area`——写反会算出超过 100% 的出租率）；同一合同内楼层不可重复 |
| 水电表 | 表号必填且园区内唯一；设备号全运营方唯一；倍率 > 0；安装位置必须在本表所属园区内；厂房楼层与宿舍楼层至多挂一处（`check_single_location`；两者都为 0 合法，表示园区公共区域表）；水表强制关闭分时 |

两条业务阻挡规则：电表关闭分时前，若有合同已约定分时电价则拒绝；水电表删除前，若被未删除的合同引用则拒绝。

### 4.3 删除即归档：软删除与级联/阻挡

本模块**没有硬删除**。一切删除都是置 `is_deleted` 标记——延续原系统语义：数据不删除，只从台账里隐藏。前端删除确认框的文案与之同口径（「这是逻辑删除，数据不会被真正删除」）。

删除园区（`park/deletion.rs`）执行一套显式的子表处置清单，每张挂园区的表登记为两类之一：

| 处置 | 表 |
| --- | --- |
| **级联注销**（纯资产台账，随园区一起隐藏） | 厂房、宿舍、水电表、园区图片、园区授权关联（`user_park` / `role_park`） |
| **阻挡删除**（带账记录或无软删标记，删了就是丢数据） | 租赁合同、租金账单、财务流水、投资记录、报销、六张运维表（消防/变压器/电梯/维修/卫生检查/厂房维保，合并计为「运维记录」）、三张门禁表、请假记录 |

存在阻挡项时删除被拒绝，提示逐类列出数量并引导改用「**停用**」——停用只改状态标记，台账保留、统计照常；这是「园区还在经营但暂不对外」与「园区彻底退出台账」两种诉求的分界。

处置清单的完备性有两道保障：`ParkChild` 枚举上的编译器完备 `match`，以及「所有挂园区的表都已登记」测试——新增一张挂 `park_id` 的表而不登记处置方式，编译或测试立即失败。

一个配套机制：`require_park_access_unless_archived`——园区已归档后，其名下残留资产的清理操作放行园区范围检查（否则园区删了、厂房还挂在台账上，谁都清不掉），但运营方隔离仍然生效。

## 第五章　权限

判定口径前后端一致（前端 `src/permissions/rental.rs::can_manage_rental`，服务端 `require_rental_manager`）：

- **谁能管**：`Super`，或持有 `/system/park` 或 `/rental/manage` 菜单（或对应权限码 `system:park` / `rental:manage`）的角色；
- **管到哪**：写入挂园区的数据前逐一校验 `require_park_access`——园区经理只能操作园区授权范围内的园区（权限模型设计.md §3.3）；
- **覆盖面**：园区、厂房、楼层、宿舍、水电表的全部 21 个写入 Reducer 均受 `require_rental_manager` 保护；前端以同一判定控制「新增/编辑/删除」按钮的显隐——按钮隐藏是体验，服务端门卫才是边界（权限模型设计.md §6.2）；
- **只读汇总**：租赁总览页不单独配菜单，持有租赁模块任一菜单即可访问。

## 第六章　与其他模块的关系

| 模块 | 关系 |
| --- | --- |
| 合同管理 | 合同主档挂园区（`park_id` 外键）；合同占用哪些楼层记录在「合同—楼层」关联表——本模块的已出租面积与出租率由此算出 |
| 财务 / 账单 | 流水与账单挂园区；是删除园区的阻挡项 |
| 维护管理 | 六张运维表挂园区（部分另挂厂房）；园区档案页只读展示最近一次检查；是删除园区的阻挡项 |
| 门禁 | 车辆、访客可选挂靠园区（未分配为合法状态） |
| 智能水电表管理 | 经水电表的 `external_device_id` 衔接；绑定操作在智能水电表管理页，绑定后账单可自动带入读数（[智能水电表管理.md](智能水电表管理.md)） |
| 数据地图 | `/data-map` 的园区放射簇画的正是本模块维护的对象层级与关联质量 |
| 权限管理 | 园区授权（`RolePark` / `UserPark`）的标的就是本模块录入的园区 |

一句话收束：**其他模块记录「园区里发生了什么」，园区管理定义「园区是什么」**——它是全部业务数据的挂靠骨架，也是园区经理权限范围的度量单位。
